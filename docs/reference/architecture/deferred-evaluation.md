# 遅延参照の評価

`ref()`は最終Bundleに含まれるNodeを参照するため、通常の式評価では参照先を確定しません。式が遅延参照に依存する場合は評価内容とClosureを保持し、Artifact集合の確定後に再開します。

遅延式の再開には、Bundle参照解決が使うNode索引、循環検出、評価budgetを共有します。新たにNodeを含む値が生成された場合はNode索引を更新してから、残りの参照を解決します。

Node索引の構築・更新は全Valueの走査ごとに同じstep budgetを消費します。確定処理で索引を何度も再構築すると、式の評価量とは別にbudget上限へ達する可能性があります。局所更新へ移る前に、評価stepと索引維持費用の上限を分ける方針を定めます。

`filter`と`exactlyOne`は述語Lambdaの本体やClosureが遅延参照を含む場合、呼び出し全体を保留します。Bundle確定後に各項目の述語を実行し、述語結果を同じ参照解決処理へ渡してからBool型を検査します。ユーザー関数を介した参照とClosure内のMap、List、Node値も遅延判定の対象です。
